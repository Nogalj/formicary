# Formicary -- implementation decisions log

Running log of implementation-level choices the spec left open. Design forks that
meaningfully change gameplay go to Logan instead of here.

## M0 Bootstrap

- **`reference/` copied from ModTest** rather than re-extracted: identical version pins
  (MC 1.21 / NeoForge 21.0.167 / Parchment 2024.11.10), so the decompiled sources are
  the same artifact. Gitignored, regenerable.
- **No Config class in the bootstrap** -- ModTest's main class carries an example config;
  Formicary starts without one and adds config only when a real tunable needs it.

## M3b Colony anger, Chitin Armor, fabric gate

- **Anger state lives on the soldier, via vanilla `NeutralMob`.** The interface is a real
  fit: the state a provoked soldier needs is exactly "ticks left + who I'm angry at", and
  it already ships the NBT round-trip (`AngerTime` / `AngryAt`), `isAngry()`,
  `isAngryAt()`, `stopBeingAngry()` and forgive-on-death. So it was adopted rather than
  hand-rolling an attachment.
- **...but `NeutralMob#updatePersistentAnger` is NOT used.** Vanilla's version re-points
  the persistent anger target at whatever the mob's current target happens to be, so a
  skeleton arrow landing on a soldier would install a *mob* UUID as "the colony's
  offender" and flip the soldier into colony-anger mode over something the colony never
  cared about. `SoldierAntEntity.customServerAiStep` decrements the timer itself instead,
  and `angerAt(Player)` is the only writer of the anger target -- so it is always a
  player. Personal retaliation still works through the untouched vanilla
  `HurtByTargetGoal`.
- **Soldier `FOLLOW_RANGE` is pinned to `ColonyAnger.ANGER_RADIUS` (24).** `TargetGoal`
  measures both its search area and its give-up distance with that attribute; left at the
  default 16 an angered soldier would forget a target still well inside the anger radius.
- **Worker flee state is a plain int + UUID on the entity**, saved under `FleeTime` /
  `FleeingFrom`. No `NeutralMob` there -- workers never target anything, so the interface
  would be all cost and no benefit.
- **Line of sight is left at vanilla's default.** `TargetingConditions.forCombat()` checks
  it, so an angered soldier behind a wall will not lock on through the wall. Deliberate:
  matching vanilla's feel beat inventing a through-wall rule the spec never asked for.
- **Chitin Armor is creative-only until M8.** No recipes exist yet (M8 owns recipes), so
  the four pieces reach the player only through the Formicary creative tab.
- **Iron-grade means iron's exact numbers**: defense 2/6/5/2, durability factor 15,
  enchantability 9, toughness and knockback resistance 0. Tunable in one place
  (`ModArmorMaterials`).
- **The mining gate is two independent halves.** Speed lives in a `PlayerEvent.BreakSpeed`
  handler (divide by 25); drops live in a datagen loot condition
  (`formicary:wearing_full_chitin`) wrapping each fabric block's self-drop pool. Both call
  `ChitinArmor.hasFullSet`. Keeping drops in the loot table rather than in the break
  handler means a datapack can retune the gate without touching Java.
- **The loot condition reads `THIS_ENTITY`, which `LootContextParamSets.BLOCK` declares
  OPTIONAL** -- so it uses `getParamOrNull` and a non-player break (TNT, piston) simply
  fails the condition rather than throwing.
- **The disguise seam is `ColonyAnger.isDisguised(Player)`, hardcoded `false`.** Every
  "is this player a valid colony target" check routes through it, and the trigger site in
  `ColonyAnger.provoke` carries the `// M4: strip disguise here` marker.
- **GameTest structure templates are generated by `assets-src/structures.py`**, a direct
  gzipped-NBT writer with no Minecraft in the loop. Its tag layout was verified by reading
  ModTest's `platform.nbt` back rather than trusting the format from memory. A second
  48x3x5 `long_platform` exists purely so the radius boundary can be tested at a real
  distance instead of shrinking the radius to fit the standard arena.
